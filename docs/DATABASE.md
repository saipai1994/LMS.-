# Database

_Generated by `node scripts/gen-db-docs.mjs` from a migrated database. 157 tables; 155 have row-level security enabled **and forced** (every tenant-owned table; `tenants` and `schema_migrations` are the only exceptions)._

## Principles
* **One student identity.** `students` is permanent. Class placement (`enrollments`), boarder/day-scholar status (`residence_assignments`), hostel beds (`bed_assignments`) and bus routes (`student_transport`) are separate, **effective-dated** tables protected by PostgreSQL `EXCLUDE USING gist` constraints, so periods can never overlap and history is never overwritten.
* **Tenant isolation in the database.** Every tenant table has `tenant_id`, composite foreign keys `(tenant_id, id)` (so a row can never reference another tenant's row) and a forced RLS policy bound to `current_setting('app.tenant_id')`, which the API sets per transaction. Queries without tenant context return no rows.
* **Money** is stored as integer minor units (paise). Invoices, payments, allocations, refunds and the student ledger are separate tables; `ledger_entries` and the general ledger are append-only.
* **Append-only evidence** (database triggers reject UPDATE/DELETE): `audit_log`, `gate_movements`, `incident_events`, `stock_movements`, `ledger_entries`, `official_marks`, `official_mark_corrections`, `submission_history`, `medication_log`, `trip_events`, `competency_assessments`, `journal_entries`, `journal_lines`. Payslips become immutable once their run is approved. Journal entries must balance (deferred constraint trigger).
* **Idempotency** keys: `payments(tenant_id, idempotency_key)`, `webhook_events(tenant_id, event_id)`, `invoices(student_id, batch_key)`, `journal_entries(source, source_ref)`.
